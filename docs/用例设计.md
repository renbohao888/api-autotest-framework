# 用例设计说明（38 条）

## 一、等价类与边界值分析

**秒杀下单接口** 入参维度：

| 维度 | 等价类 / 边界 | 用例 ID |
| --- | --- | --- |
| 库存 | 充足（N） / 边界（1） / 边界（0） / 已被他人抢完 | SEC-001 / SEC-002 / SEC-003 / SEC-004 |
| 活动时间窗 | 进行中 / 未开始（开始前） / 已结束（结束后） | SEC-001 / SEC-009 / SEC-010 |
| 用户 | 首单 / 重复下单 | SEC-001 / SEC-005 |
| activityId | 合法 / 缺失 / 非数字 / 不存在 | SEC-001 / SEC-006 / SEC-007 / SEC-008 |
| 登录态 | 有效 token / 无 token / 伪造 token | SEC-001 / SEC-011 / SEC-012 |
| 频率 | 正常（≤3 次/秒） / 超限（>3 次/秒） | SEC-001 / 并发用例 |

**登录接口**：密码正确 / 密码错误（1001）/ 缺用户名（1003）/ 缺密码（1003）/ 参数全缺（1003）。

**并发维度**：并发用户数 200 ≫ 库存 10（保证竞争充分）；同一用户 8 并发（验证幂等与限流）。

## 二、状态迁移矩阵

订单状态：`WAIT_PAY` → `PAID` → `COMPLETED`；`WAIT_PAY` → `CANCELED` / `TIMEOUT_CLOSED`（回补库存）。

| 起始 \ 目标 | WAIT_PAY | PAID | COMPLETED | CANCELED | TIMEOUT_CLOSED |
| --- | --- | --- | --- | --- | --- |
| WAIT_PAY | — | ✅ ODR-002 | ❌ | ✅ ODR-004（回补库存） | ✅ ODR-005（回补库存） |
| PAID | ❌ | ❌ ODR-008 | ✅ ODR-003 | ❌ ODR-007 | ❌ |
| COMPLETED | ❌ | ❌ | ❌ | ❌ | ❌ |
| CANCELED | ❌ | ❌ ODR-006 | ❌ | ❌ | ❌ |
| TIMEOUT_CLOSED | ❌ | ❌ ODR-009 | ❌ | ❌ | ❌ |

✅ 合法迁移（断言目标状态 + 库存变化）；❌ 非法迁移（断言 HTTP 409 / 业务码 1010 + 库内状态不变）。

### 订单状态机（10，数据驱动 `data/order_flow_cases.yaml`）

ODR-001 初始状态 WAIT_PAY；ODR-002 待支付→已支付；ODR-003 已支付→已完成；
ODR-004 取消（回补库存）；ODR-005 支付超时关单（回补库存）；
