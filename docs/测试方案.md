# 测试方案（api-autotest-framework）

## 一、测试对象与范围

| 项 | 内容 |
| --- | --- |
| 被测系统 | 秒杀服务（SUT）：`service/`，Flask + SQLite，含库存扣减、幂等、限流、订单状态机 |
| 被测接口 | 12 个：健康检查、登录、活动查询、秒杀下单、订单查询、支付 / 取消 / 完成、超时关单、内部库存 / 夹具接口 |
| 测试类型 | 接口功能测试、鉴权与越权、异常与边界、状态机、并发与数据一致性、性能门禁 |
| 不在范围 | UI 测试、兼容性测试、安全渗透（仅覆盖登录态与越权的基础校验） |

## 二、测试策略（分层）

| 层级 | 目标 | 主要手段 | 对应文件 |
| --- | --- | --- | --- |
| 协议层 | 接口可用、响应结构统一、鉴权生效 | 状态码 / 业务码 / 字段子集断言 | `framework/assertions.py` |
| 业务层 | 业务规则正确（时间窗、限购、限流、售罄） | 等价类 + 边界值 + 场景法，YAML 数据驱动 | `data/seckill_cases.yaml` |
| 状态层 | 订单状态流转正确、非法流转被拒 | 状态迁移法（5 态、合法 / 非法组合矩阵） | `data/order_flow_cases.yaml` |
| 数据层 | 库存与订单数据正确、最终一致 | 「接口 + 数据库」双端断言、不变量校验、轮询等待 | `framework/db.py`、`testcases/test_40_consistency.py` |
| 性能层 | 响应时间与吞吐达标、错误率为 0 | P95 门禁、50 并发吞吐、错误率门禁 | `testcases/test_50_perf.py` |

## 三、环境与数据准备

- **环境**：`dev`（本地，用例自动拉起 SUT，随机端口 + 临时 SQLite 库）、`ci`（GitHub Actions，阈值放宽）；
  真实环境只需把 `sut.auto_start` 置 `false` 并配置 `http.base_url` / `database`。
- **数据隔离**：每个用例执行前由夹具调用 `/api/admin/reset` 复位库存、清空订单与限流计数；
  需要特殊前置状态的用例（库存 0/1、活动未开始 / 已结束）在 YAML 的 `setup` 中自行构造，
  因此用例之间无顺序依赖，可单独重跑、可并行扩展。
- **账号**：测试服务密码固定 `test123`；并发用例动态登录 200 个不同用户（`u_001`…`u_200`）。

## 四、用例设计方法

1. **等价类划分**：入参按有效 / 无效类划分（库存充足 / 售罄、活动进行中 / 未开始 / 已结束、
   用户名密码正确 / 错误 / 缺失、业务码 0 / 1001~1011）。
2. **边界值分析**：库存取 `0 / 1 / N`；时间窗取「开始前 / 进行中 / 结束后」；并发数远大于库存数。
3. **场景法**：主链路（登录 → 下单 → 查单 → 支付 → 完成）、异常链路（重复下单、非法状态迁移）。
4. **状态迁移法**：以 `WAIT_PAY` 为起点枚举 5 种状态的合法 / 非法迁移组合（见 `docs/用例设计.md`）。
5. **不变量校验**：并发与补偿场景不看单点结果，校验 `当前库存 + 有效订单数 = 初始库存`。

## 五、准入与准出

**准入**：被测服务 `/api/health` 返回 200；数据库可读；用例数据复位成功。

**准出**：
- 冒烟用例 100% 通过，回归用例通过率 100%，无未处理的高优先级缺陷；
- 并发用例不变量成立（不超卖、无负数库存、订单数与库存一致）；
- 性能门禁达标（P95 ≤ 阈值、错误率 ≤ 1%、QPS ≥ 阈值）；
- 报告与日志归档（`reports/report.html`、`reports/summary.json`、`reports/atf.log`）。

## 六、执行方式

```bash
python scripts/run.py smoke        # 提交前自检
python scripts/run.py              # 回归（不含性能）
python scripts/run.py concurrency  # 并发与一致性
python scripts/run.py perf         # 性能门禁
pytest -m smoke --env ci           # 切 CI 环境跑冒烟
```

## 八、风险与待确认项

1. **订单详情未校验归属**：当前接口只校验登录态，A 用户可通过订单号查询 B 用户订单
   （`testcases/test_10_auth.py::test_order_detail_ownership` 已按 `skip` 登记）。
   需产品确认是「允许凭订单号查询」还是「必须校验归属」，确认后补用例并推动修复。
2. **限流为单机内存实现**：多实例部署下限流不准确，真实环境需网关 / Redis 限流；
   用例只验证单机语义，不覆盖分布式限流。
3. **被测服务为练习实现**：SQLite 写入串行化，并发语义与 MySQL 行锁不完全等价；
   接真实库时应补充死锁、锁等待、连接池相关的专项用例。
4. **性能阈值依赖机器**：本地与 CI 阈值不同，性能用例默认不纳入每次 CI，避免误报噪音。
